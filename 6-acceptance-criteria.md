# Acceptance Criteria Starter

Use this structure:

> When [condition], [content/component/page] must [observable behavior] so that [user/task/quality goal]. I will test this by [test method].

## Criteria Drafts

1. Responsive: When users open the website on a smaller viewport, all content (such as paragraphs, tables, and forms) must adjust so that they fit comfortably onto the smaller screen. I will test this by using the Chrome Inspection Tool and by opening the site on devices with smaller viewports.
2. Responsive: When users open the website on a smaller viewport, the navigation menu must adjust to a hamburger that opens a left edge menu rather than a typical top edge one as that fits navigation links better on a smaller viewport. I will test this by using the Chrome Inspection Tool and by opening the site on devices with smaller viewports.
3. Accessibility: When a screen reader user opens the website, headers must be organized in a way where they are read in proper heading order. I will test this by looking at the accessibility tree for the webpage in the Chrome Inspection Tool.
4. Accessibility: When a keyboard navigation user uses the website, elements must be properly highlighted so that the user is able to navigate the website and select buttons easily. I will test this by trying the keyboard navigation on the website via Chrome. 
5. Browser support or fallback:  When users open the site in Chrome, Edge, or Safari, the website must have the same layout in each so that users have a similar and smooth experience using the same website across multiple browsers. I will test this by opening the site on multiple kinds of browsers.
6. Performance: When users are on slower networks, the loading times for content on the site must not be too long, so that users are able to see the content in an efficient manner. I will test this by running a lighthouse test within the Chrome Inspection tool.
7. Metadata or discoverability: When users are searching on the web, the website must be findable so that users can visit it. I will test this by running a lighthouse test within the Chrome inspection tool. 
8. Release quality: When the site is ready to be published, it must be able to pass multiple automated tests so that user are able to use it properly. I will test this by using HTML validators, CSS validators, and lighthouse.
